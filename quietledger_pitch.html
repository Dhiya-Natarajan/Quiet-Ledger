QuietLedger

Every case, on record. Every identity, off record.
A multi-tenant, consent-driven platform for civic safety & workplace complaint reporting
Team 9 — Aishwarya M Mathapati (231CS107) · Annabathula Bhavya Sri (231CS112)
Dhiya N (231CS121) · Bukke Lahari (231CS217)

Abstract

  • Civic safety and workplace complaint reporting today are fragmented and low-trust — no case tracking, no enforced anonymity.
  • QuietLedger gives every user one account with two report tracks: External (civic issues, routed to the nearest police station) and Internal (workplace complaints, routed to the organisation's HR/compliance team).
  • Anonymity is consent-driven per report, not per account — the reporter chooses disclosed or anonymous at the moment of submission.
  • Organisations are isolated multi-tenants; identity can only be bridged back from an anonymous token through a logged break-glass process run by a Platform Admin.
  • Core challenge: real two-way investigation messaging that never leaks identity unless the reporter allows it.

Research Gap

  • Existing tools (tip lines, whistleblower hotlines, HR portals) solve only half the problem:
  • — Anonymous, but no case tracking or two-way messaging, or
  • — Case management exists, but anonymity isn't actually enforced.
  • Identity/access patterns (JWT roles, OAuth) and multi-tenancy patterns (tenant_id isolation) are solved problems — not our contribution.
  • The actual gap: a consent-gated disclosure model — the same account can be identifiable on one report and anonymous on another, while still supporting stateful two-way chat with a handler.
  • True zero-knowledge anonymity + persistent login + stateful messaging is a harder research problem; we adopt consent-gated disclosure as the practical middle ground.

System Architecture

Target architecture (proposal)

  • Microservices: Account/Identity, Consent & Disclosure, Intake, Anonymisation, Geo-Routing, Tenant, Case Mgmt, Secure Messaging
  • Spring Boot + Kafka + Redis
  • PostgreSQL / PostGIS, Mongo/MinIO evidence store
  • Eureka + Config Server, Docker Compose

Initial implementation (built now)

  • Single Node.js/Express monolith
  • Auth module — JWT, 4 roles
  • Reports module — create + haversine-based routing
  • Messaging module — identity-blind by default
  • PostgreSQL, React frontend

Future Scope

  • Split the monolith into the proposed microservices as load/features grow
  • Replace haversine routing with PostGIS for true geospatial queries
  • Move messaging/notifications onto Kafka for event-driven delivery
  • Evidence notarization — hash-chained attachments for tamper-evidence
  • Dedicated Audit & Compliance Analytics service (instead of raw table queries)
  • Service discovery/config (Eureka, Config Server) and observability (Zipkin, Prometheus, Grafana)
  • Second, fully-featured admin dashboard and UI polish
